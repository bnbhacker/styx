# Styx

**Имя проекта — Styx** (решение 06.11.2026). Бренд, лого, баннер и пост — в [brand/](brand/README.md).
Механика под Elysium — в [STYX-ELYSIUM.md](STYX-ELYSIUM.md): P0 из v1.1 и кипер уже в коде, остальное там — план.

Лонг/шорт любого мемкоина против общего пула, по мотивам useinverse.xyz.
Сети: **Robinhood Chain** (основная) и **Elysium testnet** (L2 Kinetiq поверх HyperEVM,
перенос от 05.11.2026, см. «Elysium» ниже). Логика — в [SPEC.md](SPEC.md).

## Что есть

| Папка | Что | Состояние |
|---|---|---|
| `engine/` | Node: поток всех свопов RH, цены, 30-с среднее, глубина D10, допуск монет, бумажная книга, API, раздача сайта | работает на живой сети |
| `site/` | Сайт: рынки, монета с графиком и тикетом, портфель, пул, выигрыши, правила | Practice работает; Real (кошелёк и контракт) проверен на anvil-форке, ждёт деплоя |
| `contracts/` | `InversePool.sol` — ончейн-версия правил (вариант C) | 137 тестов Foundry + форки RH и Elysium, **не задеплоен, не аудирован**; подробности в [contracts/README.md](contracts/README.md) |

## Запуск

Нужен Node 20+. Один раз поставить зависимости (только `viem`), дальше из корня репо:

```bash
npm install
npm start              # тестнет Elysium, порт 4681  (node engine/elysium.mjs)
npm run start:mainnet  # мейннет Elysium, порт 4682  (node engine/elysium-mainnet.mjs)
npm run start:rh       # Robinhood Chain, порт 4680  (node engine/rh.mjs)
npm test               # юнит-тесты кипера
```

Открыть http://localhost:<порт>. Первые ~1,5 мин движок догружает историю свопов (на Elysium ~70 мин,
`BACKFILL=<блоков>`, чтобы изменить), потом список монет живой. Бумажные книги лежат в `engine/data/`
(`paper.json` для RH, `paper-<сеть>.json` для остальных).

Если исходящий трафик идёт через HTTPS-прокси из окружения, движку нужен `NODE_USE_ENV_PROXY=1` (Node ≥ 22.21).

## Мейннет Elysium (14.11.2026)

Сеть `elysium-mainnet` в `engine/config.mjs`; тестнет остался сетью `elysium` и по-прежнему выбран по умолчанию,
так что публичный стенд на тестнете этим не затронут. Все значения сняты 14.11.2026:

| | Значение | Откуда |
|---|---|---|
| chainId / RPC | 99901 / `https://rpc.elysium.kinetiq.xyz` | `eth_chainId` |
| WHYPE | `0xbA876237B0F021A6c6D852d6c26E107997cC5E81` | docs/contract-addresses, сверено с цепью |
| USDC (6 знаков) | `0xb47c4C8F73F009CC0C0d3f92B388d13E293F0B65` | docs/contract-addresses, сверено с цепью |
| Блок | ~0,23 с (тестнет: 0,107 с) | 20 000 блоков |
| Газ | base fee 0,5 gwei (в плане было 0,1) | голова цепи |
| Свопы | ~10 тыс. в час | скан 60 000 блоков |
| HYPE/USD | ≈ $68 | самый глубокий пул USDC/WHYPE |
| `getLogs` | потолок 10 000 логов на запрос | ответ узла |

- **v4:** пять PoolManager со стандартным байткодом (24 009 байт). У каждого `extsload` слота 6 вернул цену и
  ликвидность последнего свопа пула. Основной — `0xe2e1…23f1` (426 активных пулов). Два эмиттера с другим байткодом
  в список не вошли.
- **v3:** десять фабрик. Две самые крупные (`0xefd7…2891`, `0x29cd…fb41`) ищут пул по шагу тиков, а не по комиссии
  (комиссия динамическая), поэтому `verifyV3`, `v3PoolsFor` и `v3CreatedAt` теперь понимают оба вида фабрик.
- **Подделки:** монета с тикером USDC, WHYPE или HYPE, но с чужим адресом, не допускается к торговле
  (на мейннете такой «USDC» есть).

Прогон движка на мейннете 14.11: через ~1,5 мин 160 монет, 24 открыты, якорь HYPE/USD найден (11 пулов).

**Деплой на мейннет.** `NETWORK=elysium-mainnet` в `contracts/script/Deploy.s.sol` (`--rpc-url elysium-mainnet`):
- WHYPE, восемь фабрик с поиском пула по комиссии (`setFactory(f, 1)`) и две — по шагу тиков (`setFactory(f, 2)`);
- блочные параметры пересчитаны по времени под блок 0,23 с: окно исполнения 9 блоков (~2,1 с), возраст цены
  23 блока (~5,3 с), окно руга 130 блоков (~30 с). `cancelDelay` 10 с по-прежнему покрывает окно, в котором кипер
  может исполнить заявку: (9 + 23) × 0,23 = 7,4 с. Кипер считает допустимое отставание движка от этих параметров;
- для v4 при деплое разрешены только пулы **без хука** основного PoolManager. Хук лаунчпада стоит на пути свопа
  и берёт свою комиссию, поэтому каждый такой хук владелец разрешает сам (`setHookAllowed`), прочитав его код.
  До этого монеты лаунчпадов на деньги не листятся;
- прогон скрипта в режиме симуляции против мейннета 14.11 прошёл (≈ 10,5 млн газа), ничего не отправлялось.
  `testnet-deploy.ps1` на мейннет не рассчитан: он сверяет chainId 99801.

Что осталось для мейннета:
- **Экономика газа.** Base fee 0,5 gwei, в пять раз выше плана: пересчитать `minStake`, чаевые и газ сессионного ключа.
- **Пороги плеча** (150 / 45 / 9 HYPE) взяты из плана при HYPE ≈ $77; откалибровать по живым данным.
- **Хуки лаунчпадов.** Самые населённые на основном менеджере: `0x6b12…f8ec` (93 пула из 200 просмотренных),
  `0xe0de…a8ec` (16); на `0x5c54…37da` — `0x8680…6acc`. Их код не читался.
- **Эксплорер.** Адрес `https://elysium.kinetiq.xyz` взят из документации, путь `/tx/<hash>` не проверен
  (сайт отвечал 429).
- Контракт на мейннете не задеплоен, Real там не проверялся.

## Elysium (перенос 05.11.2026)

Elysium — Arbitrum Orbit (Nitro), как и RH, поэтому **контракт не менялся**. Всё сетевое
лежит в `engine/config.mjs` → `NETWORKS`.

| | RH | Elysium testnet |
|---|---|---|
| chainId / блок | 4663 / ~0,104 с | 99801 / ~0,107 с |
| Нативка и «WETH» | ETH / WETH `0x0bd7…ad73` | HYPE / WHYPE `0xcd57…f234` |
| USD-якорь | USDG | USDC `0x7d29…b47b` (6 знаков) |
| Мемкоины | Pons V2 и др., v4 | лаунчпад на v4: PoolManager `0x0088…f647`, хук `0xd492…84cc`, все пулы с нативным HYPE |
| v3 | Uniswap, Aero, форки | форк Uniswap v3, фабрика `0x520b…7893` (`setFactory(f, 1)`) |
| Метаданные и 24 ч | DexScreener | **из цепи**: DexScreener Elysium не знает |

Режим «из цепи» (`dexscreener: null`) устроен так:
- Валюты v4-пула и его возраст берутся из события `Initialize`. Для v3 это `token0/token1` и `PoolCreated` фабрики.
  Состояние v4 читается через `PoolManager.extsload` (слот 6), потому что StateView нет.
- 24-часовые сделки и объём считаются по своему потоку свопов, движок хранит сутки. Пока не набралось
  24 ч, пороги допуска масштабируются к увиденному окну: за 1,2 ч нужно 5 сделок вместо 100.
- Потолок D10 считается по балансу монеты в её v3-пуле, по споту. Без него у KALOS выходило 3,15 млн HYPE,
  с ним 133 тыс.
- **Пробелы:** у v4 потолка нет, глубина считается по ровной `L` (у лаунчпада ликвидность
  полнодиапазонная, но кастомные хуки могут врать). Вставка CA ищет только v4-пулы, а v3-монета
  появится после первого свопа. Иконок нет.

Замеры 05.11.2026: ~28 тыс. свопов в час, ~470 пулов, 421 монета, 14 открыты для торговли.
Цена HYPE на тестнете ≈ $13 300, это фантазия тестнета, поэтому пороги в долларах там
ничего не значат. Пороги плеча в HYPE (150/45/9) взяты из RH при ETH/HYPE ≈ 30: **на мейннете откалибровать.**

Найдено по дороге:
- `block.number` внутри контракта на Elysium — это **блок HyperEVM** (68,79 млн), а не Elysium
  (23,85 млн). Контракт уже берёт блоки из ArbSys: `USE_ARBSYS = 1`, `blockNumber()` совпал с
  головой (`contracts/script/live-check.ps1 -Net elysium`).
- v3-пулы тестнета держат **1 наблюдение**. `observe([30,0])` отвечает, только если свопа не было
  30 с (KALOS торгуется каждый блок и не отвечает никогда, USDC/WHYPE через раз). v3-рынок с
  ончейн-сверкой TWAP можно листить только после `increaseObservationCardinalityNext(64)`
  (вызов открытый). Иначе исполнения кипера будут падать с `OracleUnavailable`.
- Ордеринг по приоритетной комиссии (а не FCFS, как на RH): двухшаговое исполнение здесь обязательно.
- Деплой ≈ 5,55 млн газа (оценка на живой цепи), рантайм 22 003 байта.

## Кипер (Real-режим, 06.11.2026)

`engine/keeper/` — кипер InversePool v1.1. Он включается внутри движка, если задан `STYX_POOL`. Ключ берётся только из
keystore Foundry: `KEEPER_KEYSTORE` и `KEEPER_PASSPHRASE_FILE` — это пути к файлам вне репо, не сами секреты.
`KEEPER_DEV_KEY` принимается только для RPC на 127.0.0.1 (anvil).

Что делает кипер:
- исполняет открытия и USER-закрытия в окне контракта по цене движка и сначала подтягивает цену в полосу адаптера;
- отклоняет заявки с кодом (1 допуск, 2 глубина, 3 лимиты пула, 4 плечо, 5 рынок закрыт, 6 нет цены,
  7 окно пропущено, 8 пауза, 9 полоса);
- закрывает по TP/SL/кэпам с повышенными чаевыми;
- ставит `flagRug` и закрывает шорты по RUG;
- выключает рынки, у которых пропал пул;
- отправляет `reportUnrealized` раз в 10 с, а без позиций — раз в минуту как пульс.

Перед каждой транзакцией кипер её симулирует.

После ревью 06.11:
- **Привязанный пул.** Рынок, залистенный на цепи, оценивается только по пулу, к которому он привязан там
  (`v3Pool`, фид адаптера или `priceSource`). Движок держит этот пул, даже если в нём не было свопов, и не переключает
  «основной». v3-пулы принимаются только от фабрик из списка сети, с проверкой `getPool`: любой контракт может
  испустить событие `Swap`.
- **Полоса — односторонняя.** Слишком хорошая для трейдера цена подтягивается к краю полосы. Слишком плохая не
  улучшается: открытие ждёт и по концу окна отклоняется с кодом 9.
- **Порядок в тике.** Сначала проверяется свежий обвал и ставится `flagRug`, потом закрытия шортов.
- **Отчёт NAV.** Не отправляется, пока есть неподтверждённые транзакции кипера. Если движок застрял (отстаёт больше
  40 блоков или не опрашивал 5 с), кипер молчит, и аварийный выход открывается честно. После старта он 35 с прогревается.
- **Без жёстких отказов на сбоях сети.** На сбоях сети кипер повторяет попытку, а не отклоняет заявку.
  `rug` и `disable` отправляются один раз на событие. `nextId` не проскакивает непрочитанные позиции.
- **Политика охраняемого запуска на Elysium.** Ставка ≤ 5 HYPE, плечо ≤ 5x, первые сутки аккаунта ≤ 1 HYPE,
  одна сторона на трейдера в монете (коды 3, 4, 10, 12). Переопределяется через `POLICY_*`.
- **Публичный листинг.** Одна монета за раз, не чаще раза в 15 с и не больше 100 в день, все проверки до первой
  транзакции. Ошибки отдаются без URL RPC.
- Лимитер шортов инсайдеров, кластеры кошельков и второй ключ кипера сделаны 14.11, см. «Защита кипера» ниже.

Повторный e2e 07.11 после правок:
- листинг идемпотентен;
- открытие в B+1;
- ставка 30 HYPE отклонена политикой (код 3);
- закрытие исполнено, учёт = 0, NAV отправлен;
- 13 транзакций, 0 упавших.

API кипера: `GET /api/real` (статус и лог), `POST /api/real/market {token}` (листинг монеты), `GET /api/real/positions?trader=`.
API сайта — в разделе «Real-режим сайта».

Тесты: `npm test` (решения кипера, keystore, защита). Сквозной прогон 06.11 на anvil-копии

## Защита кипера (14.11.2026)

Три вещи из STYX-ELYSIUM §3.2 и §3.4, которых не хватало. Правила — чистые функции в `engine/keeper/decide.mjs`
с тестами; чтение цепи — в `holders.mjs` и `funding.mjs`.

**Кластеры кошельков (`funding.mjs`).** Кошельки с общим источником средств торгуют как один: одна сторона на
кластер в монете (код 12) и общий возраст аккаунта для лимита первых суток (код 10).
- Источник — отправитель первого простого перевода HYPE на кошелёк. Ищется только по цепи: поиск по историческому
  состоянию первого блока, где у кошелька появились баланс или нонс, потом сам перевод в этом блоке.
- Никого не связывают: депозиты моста, переводы изнутри контрактов, источник-контракт, адреса из
  `STYX_CLUSTER_EXCLUDE` и источник, оплативший больше `STYX_CLUSTER_HUB` (8) кошельков, — так отсекаются биржи и
  солверы.
- Поиск запускается на депозите в пул, по одному кошельку за раз; ответы лежат в
  `engine/data/funders-<chainId>.json`. Если ответа ещё нет, заявка ждёт в окне исполнения, а по его концу
  отклоняется с кодом 7; следующая заявка находит ответ готовым. После двух сбоев узла кошелёк торгует без кластера.
- **Ограничение:** нужен узел с историческим состоянием (оба RPC Elysium его отдают). Связь через общий сессионный
  ключ и цепочки длиннее одного перевода не ищутся.

**Лимитер шортов инсайдеров (`holders.mjs`).** F — доля запаса у десяти крупнейших держателей и у адресов, на
которые запас был выпущен. Пулы, PoolManager, burn-адреса и адреса из `STYX_HOLDER_EXCLUDE` (для мейннета там уже
контракты моста) не считаются инсайдерами, но остаются в запасе.

| F | Шорты |
|---|---|
| ≤ 20 % | без ограничений |
| 20–40 % | до 5x, номинал шортов вдвое меньше |
| > 40 % или не посчитано | до 2x, сумма max-win шортов ≤ 1 % пула |

- Отказ — код 11. Причина видна в тикете сайта (`shortLimit` в `GET /api/real/market`): «shorts limited to 2x: 91%
  of the supply sits with its largest holders».
- Балансы собираются из всей истории `Transfer` монеты (до 600 тыс. переводов), начиная с листинга, и обновляются
  раз в минуту. Хранятся в памяти: после рестарта считаются заново, до этого действует самый строгий уровень.
- **Что проверить руками:** неизвестный контракт-держатель (локер, хранилище лаунчпада) считается инсайдером. На
  тестнете у BOZO и HYPENG F вышло 91 % и 95 % именно из-за одного-двух таких адресов. Локеры надо вписать в
  `STYX_HOLDER_EXCLUDE`, иначе шорты многих монет лаунчпада останутся на 2x.

**Второй ключ кипера.** `KEEPER2_KEYSTORE` + `KEEPER2_PASSPHRASE_FILE` (или `KEEPER2_DEV_KEY` для anvil). Пока этот
адрес — кипер пула (`setKeeper(addr, true)` от владельца), через него идут защитные транзакции: TP, SL, кэпы, RUG,
`flagRug`, выключение рынка. У него свой поток нонсов, поэтому стоп-лосс не ждёт в очереди за исполнениями. Если
ключа нет или права отозваны, всё идёт через основной ключ. Статус — `defensiveLane` в `GET /api/real`.

### Сквозной прогон на форке (`engine/keeper/e2e-fork.mjs`)

Сценарий сам ничего не разворачивает: ему нужны запущенный anvil-форк, задеплоенный пул и движок-кипер.

```bash
anvil --fork-url https://testnet-rpc.elysium.kinetiq.xyz --port 8545
# деплой ключом anvil №0, кипер — anvil №1; второй ключ (anvil №2) владелец добавляет через setKeeper
cd contracts && KEEPER=<anvil №1> NETWORK=elysium forge script script/Deploy.s.sol --rpc-url http://127.0.0.1:8545 --private-key <ключ anvil №0> --broadcast
ELY_RPC=http://127.0.0.1:8545 STYX_PUBLIC_RPC=http://127.0.0.1:8545 STYX_POOL=<пул> KEEPER_DEV_KEY=<ключ №1> KEEPER2_DEV_KEY=<ключ №2> BACKFILL=3000 node engine/elysium.mjs
node engine/keeper/e2e-fork.mjs            # E2E_TOKEN=<монета v4>, по умолчанию RHSL
```

Что он делает: вносит ликвидность, заводит три свежих кошелька (два с общим источником средств), листит v4-монету
с фидом, открывает лонг, пробует встречный шорт из того же кластера, шорт выше лимита инсайдеров, затем двигает
цену пула на −8 % прямо в хранилище форка и ждёт стоп-лосс лонга и тейк-профит шорта.

Прогоны 14.11 на форке тестнета (свежий деплой каждый раз):
- RHSL (запас распределён, шорты не ограничены): 13 из 13 проверок;
- BOZO (F = 91 %): 14 из 14, шорт 5x отклонён с кодом 11, шорт 2x открыт;
- в обоих: листинг v4 с фидом, отказ с кодом 12 второму кошельку кластера, SL (причина 2) и TP (причина 1)
  отправлены вторым ключом, `accountingSurplus` = 0, 12–13 транзакций кипера, 0 упавших.

Этим закрыты оба сценария, не прогнанных 07.11: листинг v4-монеты с фидом и срабатывание TP/SL по движению цены.

**Про anvil.** Форк надолго перестаёт отвечать, если узел тестнета отказывает ему в запросе логов (anvil повторяет
отказ по 7 с и на это время блокирует всё остальное) или если в него летит много параллельных исторических
запросов. Поэтому история `Transfer` читается окнами, а не делением пополам, а поиск источников идёт по одному.
На настоящем узле этого эффекта нет: подсчёт держателей на мейннете занял 2–40 с на монету, поиск источника — ~4 с.

## Real-режим сайта (06.11.2026)

**Витрина мейннета** (`engine/showcase.mjs`, `NETWORKS.elysium.showcase`, `GET /api/showcase`): e/acc, eaccat и

берутся из полей, каждый вызов сначала симулируется против цепи, судья — контракт.

- **Кошелёк:** EIP-6963 (Rabby, MetaMask и др.) с откатом на `window.ethereum`. Сеть переключается или

  Повторный заход подключает без запроса.
- **Деньги:** депозит и вывод свободного баланса подписывает кошелёк. LP: добавить, попросить вывод (часть или
  всё), забрать после задержки, отменить. Гейт LP на запуске показывается как есть.
- **Торговля в один клик:** ключ, созданный в браузере (`localStorage`), на ≤ 24 ч по времени цепи. Включение —
  два запроса кошелька: `setSessionKey` и перевод `sessionGas` (0,02 HYPE) на газ. Ключ шлёт
  `requestOpenFor` / `requestClose` / `cancelRequest`; вывести деньги или сменить ключи контракт ему не даёт.
  Выключение возвращает остаток газа в кошелёк. Без ключа каждую заявку подписывает кошелёк.
- **Реферал:** `?ref=0x…` запоминается; первая заявка с ним идёт через кошелёк, потому что контракт привязывает
  реферера только к заявке самого трейдера.
- **Статусы:** заявка → «filling…» → тост «Filled at …» или «Refused: <причина>. Stake and fee are back».
  Причины берутся из кода отказа кипера. Закрытие показывает причину, PnL и выплату.
- **Листинг на лету:** если монета ещё не на контракте, первая заявка просит кипер её залистить.

Код: `site/real.js` (кошелёк, ключ, транзакции), `site/vendor/viem.js` (срез viem 2.55.8, 306 КБ, грузится только
в Real; пересборка `node site/vendor/build.mjs`, ищет `esbuild` и `viem` в папке над репо), `engine/real.mjs` (API), `engine/keeper/ledger.mjs`
(журнал событий пула).

API сайта (только чтение; всё подписывает браузер):

| Путь | Что |
|---|---|
| `GET /api/real/config` | сеть, пул, публичный RPC, параметры, политика запуска, тексты причин отказа |
| `GET /api/real/abi` | ABI пула и ошибки адаптера |
| `GET /api/real/account?trader=` | свободный баланс, сессионный ключ, позиции с отметкой и PnL (`null`, пока пул рынка не прочитан), `settling`, пока журнал не догнал книгу кипера, `closeRejected` / `closeCancelled`, история, LP-доля и заявки на вывод (кэш 1 с) |
| `GET /api/real/market?token=` | залистена ли монета, `fed` (есть ли у v4-рынка фид V4SpotSource), `spot` / `twap` из пула, к которому рынок привязан (как `priceEth` / `twapEth` в `/api/market`; `null`, пока пул не прочитан), запас по сторонам (кэш 2 с, сбрасывается после листинга) |
| `GET /api/real/pool`, `/feed`, `/wins` | пул из контракта (с `keeperGone`: вывод LP без задержки, как `_keeperSilent(lpEmergencyDelay)`), лента, выигрыши из журнала |
| `POST /api/rpc` | узкий JSON-RPC прокси для ключа и чтений |

Промахи кэша `/api/real/*` идут в корзину на клиента (60, +6/с) и общую; сверх лимита — HTTP 429.

**Прокси `/api/rpc`.** Пускает 12 методов чтения и `eth_sendRawTransaction`. `eth_call` идёт только в пул и
адаптер. Лимит — корзина на клиента (120 запросов, +12/с) и общая на всех (400, +150/с). Временные сбои — не
HTTP-ошибка, а JSON-RPC ошибка в ответе на каждый запрос при HTTP 200, которую viem повторяет: лимит —
`-32005`, сбой или таймаут узла — `-32603`. HTTP 400 — только на битое тело. На запрещённый метод — `-32601`:
viem сначала пробует `eth_fillTransaction` и на ошибке спокойно откатывается. Клиента за обратным прокси
определяет `STYX_TRUST_PROXY` (ниже).

**Журнал (`ledger.mjs`).** Сам находит блок деплоя (бинпоиск по `eth_getCode`, иначе файл forge broadcast,
иначе `eth_getLogs` по событию конструктора; или `STYX_FROM_BLOCK`), читает
события пула окнами с адаптивным размером и хранит их в `engine/data/ledger-<chainId>-<pool>.json`. После
рестарта продолжает с места. Кипер журналу не доверяет: он по-прежнему опрашивает `getPosition`.

**Наблюдатель.** Если `STYX_POOL` задан, а ключа нет (или ключ не кипер), движок синхронизирует книгу только
на чтение. Сайт работает с такого движка полностью, кроме листинга новых монет.

Переменные: `STYX_PUBLIC_RPC`, `STYX_EXPLORER` (по умолчанию для тестнета Elysium — Blockscout от Conduit
`https://explorer-elysium-testnet.t.conduit.xyz`, ссылки `/tx/<hash>`), `STYX_SESSION_GAS`, `STYX_FROM_BLOCK`, `STYX_TRUST_PROXY` — сколько обратных прокси стоит перед
движком и дописывает `X-Forwarded-For` (по умолчанию 0: клиент = адрес сокета, заголовок не читается). При N > 0
клиентом считается N-й адрес справа в `X-Forwarded-For` (если адресов меньше — адрес сокета); всё, что левее,
пишет сам клиент. IPv6-клиенты считаются по /64. Ставить ровно по числу своих прокси: больше — и лимиты можно
обойти подделанным заголовком.

## Деплой в тестнет Elysium (готовность 07.11.2026)

Запускается руками в своём терминале, пароли спрашивают `cast` и `forge`; ключи и пароли не попадают ни в
окружение, ни в репо:

```powershell
cd contracts
powershell -ExecutionPolicy Bypass -File script\testnet-deploy.ps1 -Lp 0xСвойКошелёк
```

Скрипт `contracts/script/testnet-deploy.ps1`:
1. проверяет `-Lp` до любых паролей, потом сверяет chainId (99801);
2. создаёт или импортирует два keystore Foundry: `styx-owner` (деплой, владелец) и `styx-keeper` (горячий ключ кипера).
   Пароль нового keystore просит ввести второй раз; при расхождении удаляет только что созданный файл. Ключи обязаны
   различаться;
3. проверяет балансы: владельцу ≥ 0,01 HYPE, киперу советует ~0,2 HYPE;
4. спрашивает `yes` (показывает RPC, владельца и кипера) и гонит `Deploy.s.sol` с `KEEPER` = адрес кипера;
5. требует успешную квитанцию у **каждой** транзакции в `broadcast/…/99801/run-latest.json`: forge выходит с кодом 0,
   даже если выкинул транзакцию после одного ответа 502 от узла (тогда — `--resume`). Сразу печатает адреса;
6. проверяет `isKeeper` и `USE_ARBSYS = true`; при `false` останавливается (это не Nitro, например форк);
7. с `-Lp` вносит свой кошелёк в список LP (гейт LP на запуске);
8. печатает, как записать файл пароля кипера (UTF-8, проверка через `cast wallet address --password-file`), и команду
   движка: `ELY_RPC`, `STYX_POOL`, `STYX_FROM_BLOCK`, `KEEPER_KEYSTORE`, `KEEPER_PASSPHRASE_FILE`.

Если forge упал на полпути, скрипт **не** деплоит второй пул: он предлагает набрать `resume` и дослать тот же деплой
(`forge … --resume`), а при отказе печатает эту команду одной строкой с полным путём к `forge.exe`. Квитанции,
потерянные forge после ответа 502 от узла, скрипт досматривает на цепи. Коды выхода: 0 — готово; 1 — остановлен
(текст объясняет, есть ли уже пул); 2 — пул задеплоен, но шаг остался (allowlist LP или проверка), команда напечатана.
Опасные переменные окружения (`ETH_PASSWORD`, `CAST_PASSWORD`, `ETH_KEYSTORE`) останавливают скрипт до паролей, а
`GUARDIAN` / `TREASURY` / `REBATE_SOURCE` / `MAX_POOL_CASH` показываются в вопросе `yes`.

**Пароли — только ASCII, раскладка английская.** Скрытые подсказки Foundry в консоли Windows (кодовая страница 866)
не принимают кириллицу. Подсказка адреса оставляет пустую строку в stdout, поэтому скрипт выбирает адрес по шаблону.
Ревью 07.11 в настоящей консоли PowerShell 5.1 нашло, что первая версия скрипта из-за этого вообще не деплоила.

В логе forge строка `USE_ARBSYS false` — это локальная симуляция без прекомпайлов Nitro. Настоящее значение скрипт
читает с цепи после деплоя.

Стоимость: деплой ≈ 0,001 HYPE (газ ~0,1 gwei). Листинг v3-монеты кипером начинается с
`increaseObservationCardinalityNext(1000)` у её пула: 22,4 млн газа (≈ 0,003 HYPE), под лимитом Nitro на транзакцию
(32 млн). На anvil-форке эта транзакция майнится минутами: каждый новый слот форк тянет из сети.

Эксплорер тестнета: `https://explorer-elysium-testnet.t.conduit.xyz` (`/tx/<hash>`, `/address/<a>`).

ABI для движка лежат в `engine/abi/*.json` (движку не нужен `contracts/forge-out`). После правки контракта:
`forge build`, затем `node engine/abi/sync.mjs`.

## Дизайн (29.10.2026, черновик до имени)

Одна идея — **горизонт**. Экран поделён линией: сверху «день» `#E6EAF0`, снизу «ночь»
`#0E1013`. Лонг живёт над линией, шорт под ней, сама линия — пул. Весь интерфейс —
один белый слой в `mix-blend-mode: difference`, поэтому текст, графики и кнопки сами
инвертируются, когда пересекают линию. Акцент `#C8BF1A` в этом режиме становится
кобальтом над линией и натриево-жёлтым под ней. `#000` внутри слоя — «дыра» в мир,
им маскируется то, что уезжает под шапку и тикет.

- Тикет на странице монеты прибит к горизонту: «Long» над линией, «Short» под ней,
  ставка лежит на самой линии и разрезана пополам. На телефоне горизонт опускается
  к тикету внизу.
- Ширина шрифта — данные (Anybody, ось wdth 50–150): ширина тикера = глубина монеты
  (D10), ширина слов long/short на главной = доля открытых денег в эту сторону.
- Направление — стрелками ↑/↓, без зелёного/красного: на странице одна краска.
- Шрифты: Anybody (заголовки), Instrument Sans (текст), Martian Mono (цифры).

## Как движок видит «любую монету»

Раз в 1.5 с — один `eth_getLogs` по двум топикам `Swap` (v3 и v4) без фильтра
по адресу. Это все свопы сети: Uniswap v3, Aero Slipstream, v3-форки
лаунчпадов, все v4-пулы (Pons V2 после градуации, Doppler/Long.xyz, хуки).
Каждый своп несёт `sqrtPrice` и `liquidity`, так что состояние пулов отдельно
читать не нужно. Какой токен в пуле и какая котировка — из DexScreener
(для v3 есть фолбэк через `token0()/token1()`). 24-часовые объёмы и число
сделок для допуска — тоже DexScreener. Цены — только из цепи.

Сверка 29.10.2026: 196 из 200 монет совпали с ценой DexScreener в пределах 10%.

## Подводные камни, найденные по дороге

- Нода RH отдаёт `blockTimestamp: "0x0"` у свежих блоков — время свопа берётся
  с часов движка.
- Многие v4-мемкоины котируются в USDG, не в ETH.
- Формула глубины с ровной ликвидностью завышает узкие диапазоны в десятки раз —
  стоит потолок по ликвидности DexScreener.
- Два пула одной монеты стоят на разной цене; переключение основного пула
  без гистерезиса ложно взводило rug guard.
- Токенизированные акции Robinhood (SPY, NVDA, TSLA…) тоже проходят допуск —
  механика к ним применима, но это решение продукта, а не движка.
